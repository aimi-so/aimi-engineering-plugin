# command-blocks-baseline.txt — known findings for test-command-blocks.sh
#
# Format, tab-separated:  <check>  <file>  <key>  # <reason>
#   check  : syntax | portability | loop-scope | unassigned | argument-gate
#   file   : relative to commands/, or `skills/`-prefixed and relative to the
#            plugin directory — the two roots the extractor reports against
#   key    : the block's enclosing heading (syntax, portability)
#            the variable name             (loop-scope, unassigned)
#   reason : REQUIRED, one line, on the entry itself
#
# Blocks are keyed by heading rather than by a marker in the markdown because
# install.sh translates command bodies for OpenCode by pure string
# substitution — anything embedded in the file itself would ship to users.
#
# A line here is a promise that someone looked, and the reason field is what
# makes that promise per-line instead of per-section. The suite strips the
# field before matching, so it changes no key; it exists because a paragraph
# above a list is free to describe the list and then stop being true of the
# entry someone appended to the bottom of it. The section prose below still
# explains each class — the field says what THIS line is.
#
# The suite fails when a listed finding stops firing, so this file shrinks as
# things are fixed; it cannot quietly accumulate. Delete the line when you fix
# the thing.
#
# skills/ joined the corpus after everything above it was already here: a
# SKILL.md is executed exactly the way a command file is, and until then no
# static analysis reached one at all. Four entries arrived with it, each in
# the section for its own class rather than in a section of their own — they
# are the same four kinds of finding, not a new kind.
