# Hook Guards

Plugin development notes, moved out of `plugins/aimi-engineering/CLAUDE.md` so that file loads whole. Read this when you change a hook handler, a guard's allow/deny rule, or a bypass env var.

### Staging-file guard

`hooks/guard-runtime-state.py` — the `Write|Edit` PreToolUse hook registered in `hooks/hooks.json` — refuses a hand edit of a **staged story file**: a target whose last four path components are `.aimi/.tasks-staging/<run>/NN-*.json`. The rule is judged from the resolved target's components alone, never from the working directory, so a run directory under a worktree's own `.aimi/` is treated like the main checkout's.

- **Denied:** any tool other than `Write` (so `Edit`, by anyone), a `Write` over an existing story by the main session, and a `Write` over an existing story that has a validation stamp beside it, whoever the caller is. The denial is the structured `permissionDecision: deny` at exit 0, like the hook's other blocks that point at a verb, and its message names both sanctioned routes: `apply-audit-patches` (see its section under Story Lifecycle Subcommands), or delete the file and re-run the expander.
- **Allowed:** a `Write` that creates a file that does not yet exist (that is the story expander's own output); a `Write` over an existing story **by a subagent while no stamp exists beside it** (the expander fixing the validation defect it was re-spawned for); the sidecars `outline.json`, `metadata.json`, `audit-result.json` and any `*-outline.json` (the name rule is the one `story_merge.py`'s `is_sidecar` applies in the other direction, so the hook and the merge agree on what a story is); and an `NN-*.json` outside a `.tasks-staging/` run directory.
- **The validation stamp.** `NN-<slug>.json.validated` beside a staged story is the orchestrator's record that the story passed Schema Validation steps 2 and 2b (`commands/references/plan/phase-3d-validate-retry.md`); it holds the sha256 hex of the story file. The hook compares nothing inside it: the file's existence alone closes the story to every Write and Edit, which fails closed, and the digest is there so a later reader can tell whether the file changed after validation (for example after `apply-audit-patches` rewrote it). The stamp name never ends in `.json`, so `story_merge.staging_files` (which globs `*.json`) and `audit_patches.staged_idx_map` (which full-matches `...\.json`) never read it as a story, and `outline-shift` renames it and deletes it together with its story file. The hook denies **any subagent Write or Edit of a stamp** in every state, and leaves the main session free to write one. The stamp name is never judged as a story or a sidecar.
- **The subagent signal.** `is_subagent_write(payload)` is true when the hook payload carries a non-empty `agent_type` or `agent_id`; the main session carries neither. It reads the dict the hook already reads `tool_name` from. `staging_stamp(path)` derives the stamp path from a story path.
- **The expander context directory.** `<RUN_DIR>/context/` holds the shared blocks every expander of a run reads (`commands/references/plan/phase-3d-context-files.md`: the outline, the consolidated research, the resolved decisions, the specs and the other blocks of its table), written once by the orchestrator with the Write tool. The hook denies **any subagent Write or Edit at or below a `context` directory two components under `.aimi/.tasks-staging/`** (`_is_expander_context_dir`, judged from path components alone like the story rule, so a worktree-nested run directory is treated like the main checkout's), and leaves the main session free to write there. The reason is that one expander able to rewrite a file its siblings read would change what they are told. `story-merge` and `apply-audit-patches` never list the directory as a story, and `story-merge` removes it together with the run directory. The rule inherits the guard's limits below: Bash, OpenCode and `AIMI_RUNTIME_STATE_GUARD=off` walk past it.
- **Why:** once a story is expanded and audited it is consistent with its siblings, and a hand edit drifts it out of that consistency while leaving the audit result describing text that no longer exists. The sanctioned edit path validates, sanitizes and writes atomically.
- **It is a guard rail against accidental edits, not a security boundary, and the hook's own docstring says so.** What walks straight past it: a Bash command (`sed -i`, `jq … > file`, a redirect) because the hook is registered on `Write|Edit` only; an OpenCode session, because `install.sh` wires no hooks; `AIMI_RUNTIME_STATE_GUARD=off`, which disables every block in the file; a staging directory that is not under `.aimi/.tasks-staging/`; the `exists()` check, which is not atomic with the write that follows it; and a subagent overwriting a **sibling's** unstamped story, because the hook knows that a subagent is calling but not which story it was handed (a known bypass beside Bash). OpenCode wires no hooks, so there the stamp is instruction-only. Do not build a guarantee on it. The gate that makes a skipped audit visible is the one in `story-merge`, not this hook.
- **Tests:** the `test_staged_story_*` cases in `hooks/tests/test_runtime_state_guards.py` cover a new file, an `Edit`, a `Write` over an existing file (and that the reason names both routes), the sidecars, a same-named file outside `.tasks-staging/`, a worktree-nested run directory and the env bypass. The `test_stamp_*`, `test_is_subagent_write_*` and `test_staged_*subagent*` cases beside them cover the subagent signal, the unstamped subagent rewrite, the stamped and main-session denials, the stamp deny for subagents, the main session's free stamp write, and the stamp name never being judged as a story. The `test_expander_context_*` cases cover the context directory: a subagent's Write and Edit denied, `agent_id` alone enough, the main session allowed, lookalike paths outside a staging run allowed, a worktree-nested run directory, the component-only predicate and the env bypass. The stamp is also pinned from the other side: `test_outline_shift_stamp_*` in `scripts/tests/test_outline_contract.py` (rename, delete, no orphan) and the stamp-ignored cases in `test_story_merge.py` and `test_audit_patches.py`.

### Raw forge write guard

`handle_raw_forge_write` in `hooks/pre-bash-dispatcher.py` refuses a raw `gh` or `glab` write that one of the forge verbs can express, and points the caller at the verb. It maps five verbs: `gh pr create` and `glab mr create` to `forge-pr-create`, `gh pr edit` and `glab mr update` to `forge-pr-edit`, `gh pr merge` and `glab mr merge` to `forge-pr-merge`, `gh issue create` and `glab issue create` to `forge-issue-create`, and `gh release create` and `glab release create` to `forge-release-create`. The denial is the structured `permissionDecision: deny` at exit 0, like the hook's other blocks, and it names the verb, its usage line and the bypass.

- **What it refuses is narrow on purpose.** The command is parsed against the verb's own flags, and it is refused only when the verb could have done the whole job. A flag the verb cannot express (`--draft`, `--fill`, `--delete-branch`, `--label`, `--notes`), a positional past the verb's, a `--` terminator, an unterminated quote or a short flag glued to its value passes, because refusing it would send the caller to a verb that cannot do the work. It judges only inside a project with a `.aimi/` directory, and only for the pair the remote resolves to (`gh` on GitHub, `glab` on GitLab).
- **What it never sees.** `gh api` and `curl` against a forge endpoint, `bash -c '...'`, `xargs gh ...`, a path-qualified `/usr/bin/gh` or `command gh`, a call inside a script the AI writes and then runs, and the plugin's own verbs (their `gh` call runs inside `aimi-cli.sh`, which this hook never reads). It is a guard rail against a habit, not a security boundary.
- **It fails open.** The dispatcher's `main` is wrapped in `safe_hook`, so a parse error or an unexpected exception exits 0 and allows the command instead of blocking it.
- **OpenCode does not run it.** `install.sh` wires no hooks, so on OpenCode the only gate is the confirmation `skills/forge/SKILL.md` asks for.
- **The bypass is `AIMI_FORGE_GUARD=off`, exported before the session starts.** An `inline prefix` (`AIMI_FORGE_GUARD=off gh pr create ...`) never reaches the hook, which reads the environment of its own process. See `## Guard Bypass Envs`.
- **Tests:** `hooks/tests/test_guard_raw_forge.py`, run with the rest of `python3 -m pytest plugins/aimi-engineering/hooks/tests/ -q`.

## Guard Bypass Envs

Hooks support per-guard bypass via environment variables. Set `<name>=off` (or unset to leave the guard active). Bypass is intentional escape hatch — use sparingly and document why.

| Env Var | Hook | Behavior when `off` |
|---|---|---|
| `AIMI_DEFAULT_BRANCH_GUARD` | pre-bash-dispatcher (default-branch handler) | Allows commits on protected branches (main/master/develop) |
| `AIMI_SHELL_TRUE_GUARD` | pre-bash-dispatcher (shell-true handler) | Allows commits with shell=True in staged Python files |
| `AIMI_WORKTREE_BUDGET_GUARD` | pre-bash-dispatcher (worktree-budget handler) | Allows git worktree add beyond metadata.maxConcurrency |
| `AIMI_RUNTIME_STATE_GUARD` | guard-runtime-state | Allows direct Write/Edit to .aimi/state/, .aimi/tasks during execution, roadmap.json, phase-*/handoff.md, and staged story files (`.aimi/.tasks-staging/<run>/NN-*.json`) |
| `AIMI_FORGE_GUARD` | pre-bash-dispatcher (raw-forge-write handler) | Allows a raw `gh`/`glab` write that a forge verb can express; export it before the session starts, since an inline prefix never reaches the hook (see `### Raw forge write guard`) |

> `AIMI_RUNTIME_STATE_GUARD` (`guard-runtime-state.py`) intercepts the Write/Edit tool path and blocks direct writes to `roadmap.json` and `phase-*/handoff.md` (see `docs/dev/roadmap.md` § Roadmap File Schema) the same way it blocks `.aimi/tasks/*-tasks.json`, pointing the caller at the `roadmap-*` aimi-cli.sh verbs instead. This coverage is Write/Edit-tool-only — the hook is registered on `matcher: Write|Edit` (`hooks/hooks.json`) and reads `tool_input.file_path`. A Bash command that writes either file directly (e.g. `jq ... > roadmap.json`) is **not** intercepted.
