# aimi-cli.sh Research, Spec and Environment Subcommands

Plugin development notes, moved out of `plugins/aimi-engineering/CLAUDE.md` so that file loads whole. Read this when you change the research, spec-derivation, `check-version`, `slugify` or `detect-design-bundle` verbs.

## aimi-cli.sh Research Subcommands

Two CLI subcommands manage the research lifecycle. Both are internal — consumed by `plan` and `deepen` commands, not invoked by users directly.

- **`research-lookup <path>`** — Content-aware freshness check. Reads the `## File References` h2 bullet section of the given research `.md` file, compares its mtime against the newest mtime of every cited source path, and exits 0 (fresh) or 1 (stale). Cited paths that are missing or outside the project root are treated as stale. Used by `plan`/`deepen` before deciding whether to spawn a researcher.

- **`extract-sections <file> --anchors "<titles>" [--all-headings]`** — Prints the requested sections of a research file. It matches a heading of any level two or deeper (`##`, `###`, `####`, ...), not only `##`; an h1 is never matchable. A section runs from its heading to the next heading of the same or a higher level, so an h2 anchor includes its nested h3 lines and an h4 anchor stops at the next h4, h3 or h2. Anchor and heading are compared on one match key (`_extract_sections_match_key`): `"`, `\`, `$` and the backtick are removed, whitespace runs collapse to one space, the ends are trimmed and the result is lowercased, so the sanitized anchor `The foo flow` finds the heading `## The "foo" flow`. An anchor with no matching heading, or whose key is empty, is skipped with a `no section matched anchor` warning on stderr at exit 0. A raw anchor carrying `$(`, a backtick or `$` followed by a letter is rejected with a warning (defense in depth, since a double-quoted shell argument evaluates those before the CLI runs); a raw `"`, `\` or `$` not followed by a letter or `(` is accepted and compared by its key. The researcher templates therefore write `###` headings and may put those four characters in them: the planner strips them from the anchor and `extract-sections` strips them from the heading before comparing, and `commands/references/plan/phase-3d-prep-blocks.md` states the Step 2 sanitization rule (every `$`, backtick, `"` and `\` removed, newlines to spaces, 200-character cut) with nothing dropped afterwards. `extract-prototype-sections` keeps its own rejection of the four characters. **`--all-headings` is opt-in** and changes only what counts as a heading: a level 1 ATX heading becomes matchable, and so does a setext heading (a text line underlined by a line of only `=` for level 1 or only `-` for level 2), which also closes a section of the same or lower rank exactly as an ATX heading does. Underline lines inside a ``` or ~~~ fence, the `---` delimiters of a leading YAML front matter block (and every line between them) and a line already used as an underline are never headings. It exists for a kit handoff document under `.aimi/sources/<kit>/`, which is written in h1 and setext headings. The setext rule needs the line after a text line, so that scan is a second awk program (`_EXTRACT_SECTIONS_ALL_AWK`) that reads the whole file first; without the flag the one-line-at-a-time program runs unchanged, and its output for a file holding h1 and setext headings is byte-identical to what it was before the flag existed. Tests: `scripts/tests/test_extract_sections_all_headings.py`.

- **`research-gc`** — Orphan garbage collector. Deletes `.aimi/research/*.md` files older than 30 days that are not referenced by any active `.aimi/tasks/*.json` `metadata.researchPaths`, any `.aimi/brainstorms/*.md` frontmatter `researchPaths`, or any `.aimi/brainstorms/*.md` frontmatter `foundationProposalPath`. Called opportunistically once per `plan`/`deepen` session. Silent when nothing is removed.

## aimi-cli.sh Spec Derivation Subcommand

- **`spec-derivation --input <path>`** — Validates a research agent's entity/endpoint presence findings, shaped `{"records":[{"kind":"entity"|"endpoint","name","status":"present"|"absent"|"unchecked","evidence":[...]}]}`, and prints `{records, relabeled, markdown:{entities, endpoints}}`. A one-crossing reader with no lock, the same shape as `design-decisions`: `cmd_spec_derivation` confines `--input` with `validate_path_in_project` (it arrives as a CLI argument), calls `check_python3`, then makes exactly one crossing into `tasks.py`'s `spec-derivation` op, which owns the validation (`derive_spec_records`). `absent` is a positive claim, so a record claimed `absent` with an empty `evidence` array is relabeled `unchecked`, listed in `relabeled` as `<kind>:<name>`, and reported on stderr; a record that arrived as `unchecked` with no evidence is the genuine never-checked case and passes through unchanged, unlisted. The markdown strings hold one `| name | status-label | evidence |` row per record in input order; the status-label `unchecked (claimed absent, no evidence)` appears only on relabeled records. Malformed input exits 1 with a message naming the record index and the invalid field (`records[N].<field> ...`). Downstream callers consume this verb's output; none reimplements the validation.
- **`structural-vocabulary --tasks <path> [--spec <path>]... [--prototype <path>]...`** — Advisory count of the `STRUCTURAL_LEXICON` container/placement terms (bottom sheet, dialog, modal, ...) in a spec/prototype versus a tasks file's story text, printing `{measured, terms, missing, unsourced}`. A one-crossing reader with no lock, the same shape as `spec-derivation`: `cmd_structural_vocabulary` confines every path with `validate_path_in_project`, calls `check_python3`, then crosses once into `tasks.py`'s `structural-vocabulary` op. Matching is whole-phrase and case-insensitive (`playlist` is not `list`); `measured` is false, with empty arrays, when no term occurs anywhere. It never blocks; the caller decides how to present `missing` and `unsourced`.

## aimi-cli.sh Audit Open Subcommand

- **`audit-open [--tasks-file <path>]`** — Prints `{"count": N, "findings": [{"message": str, "stories": [str]}]}` from `metadata.auditOpen` (the audit findings a plan left open), and answers count 0 with an empty list when the key is absent. A one-crossing reader with no lock and nothing written: `cmd_audit_open` confines `--tasks-file` with `validate_path_in_project` before `python3` starts (else it takes `get_tasks_file`), calls `check_python3` and refuses without the interpreter, then crosses once into `tasks.py`'s `audit-open` op. A value that is present but not an array of `{message, stories}` objects exits 1 naming the file, so an unreadable list is never read as nothing open. Its one caller is the Open Audit Findings entry of `commands/execute.md` (`references/execute/step-1-audit-open.md`), which lists the findings once per top-level run and asks, in picker mode, whether to run anyway; no command body reads `auditOpen` with `jq`. It is on `hooks/auto-approve-cli.sh`'s read-only whitelist. Tests: `scripts/tests/test_audit_open.py`.

## Environment and helper subcommands

### `branch-divergence`

`branch-divergence [--branch <name>] [--project <path>]` prints `{"branch","divergence","ahead","behind"}` for a local branch against `origin/<name>`. `divergence` is `_branch_divergence`'s answer (`none`, `in-sync`, `local-ahead`, `local-behind`, `diverged`), the helper `resolve-base-branch` already used for its `baseDivergence`. It compares the two refs as the last fetch left them and never contacts the remote, so the caller decides when to fetch; plain Bash, no `python3`. `--branch` defaults to the current branch and `--project` to the caller's directory, like the other branch verbs. A detached HEAD and a branch origin does not have answer `none`. The name is printed inside a JSON string and handed to git as a ref, so an explicit `--branch` outside `^[a-zA-Z0-9][a-zA-Z0-9/_.-]*$`, or holding `..`, is refused. `/aimi:plan` calls it with `--project "$AIMI_ROOT"` right after its fetch (`commands/references/plan/step-0-environment-setup.md`), and `step-0-branch-freshness.md` acts on `local-behind` and `diverged`; a multi-repo layout is not checked. It is in `hooks/auto-approve-cli.sh`'s read-only list. Tests: `scripts/tests/test_branch_divergence.py`.

### `check-version` and the global cli-path pointer

`check-version` used to compare only the PROJECT pointer (`.aimi/cli-path`) against the newest install, and treated the machine-wide pointer (`~/.config/aimi/cli-path`, or `$AIMI_CONFIG_DIR/cli-path`) as something to overwrite once the project pointer was found stale. A project whose own pointer was `current` or absent therefore never looked at the global one, so a session in any other project kept resolving an older install, or one under a second Claude config root. `_check_version_global_pointer` now compares it too, and the JSON gains a `globalCli` object `{status: "stale"|"fixed", storedVersion, latestVersion, storedPath, latestPath}` (with `reason` when a repair is declined). When the project pointer is `current` or `missing`, the top-level `status`, `storedVersion` and `latestVersion` are the global pointer's; when the project pointer is itself `stale` or `fixed`, its own JSON is unchanged and `globalCli` sits beside it. Without `--fix` a stale global pointer exits 1.

- **`--fix` writes only after the target survives four checks** (it exists, is executable, is named `aimi-cli.sh` and sits under an `x.y.z` version directory) and reports `fixed` only after re-reading the pointer, because `write_global_cli_cache` declines a `/.worktrees/` path as a no-op success. A repair it cannot confirm leaves `globalCli.status` at `stale` with a `reason`, at exit 0.
- **Nothing is reported or written** when the pointer is current, missing, empty, legacy-file-only or not a versioned plugin-cache path, and never under `AIMI_DEV_DIR`, the converter branch, a valid `AIMI_CLI_PINNED` or a directory-source install. The legacy `~/.claude/aimi-engineering-cli-path` is a read fallback only and is **not repaired**.
- **Known remaining gap.** When the PROJECT pointer is stale and `--fix` runs, the older project-fixed branch still writes the global pointer through the unvalidated `write_global_cli_cache` path rather than through the four checks above. The user-facing contract is in `commands/references/cli-path-resolution.md`; `scripts/tests/test_version_cache.py` pins the verb.

### `slugify`

`aimi-cli.sh slugify (--stdin | <text>)` prints an ASCII directory slug and is the deterministic form of `commands/references/topic-slug.md`'s five steps, for a caller that names a directory after the result. It is dispatched ahead of `find_aimi_root`, so it answers from any directory, takes no tasks file and no lock, and passes the text straight to `scripts/slug.py` as one argument or as stdin bytes, never through a shell. It calls `check_python3` and **refuses rather than degrades**: a slug built without the interpreter would be a different slug. The text is decomposed with NFKD and only its ASCII characters are kept, then lowercased, runs of non-alphanumerics become one hyphen, the ends are trimmed and the result is cut to 50 characters and trimmed again. **NFKD only:** a letter with no decomposition (o with stroke, sharp s, the ae ligature) is dropped, not transliterated, so `Søren Straße Ærø` gives `sren-strae-r`. Text with no ASCII letter or digit left is refused with exit 1 and nothing on stdout. `ascii_fold` in `slug.py` is also what `bundle_relevance.py` folds with. Tests: `scripts/tests/test_slug.py` and the `slugify` cases in part 2 of `test-aimi-cli.sh`.

### `inspect-prototype-kit` and `import-prototype-kit`

`aimi-cli.sh inspect-prototype-kit <path>` prints `{kind, htmlFiles, markdownFiles, otherFiles, refused, qualifies}` for a folder or `.zip` prototype kit and writes nothing; `import-prototype-kit <path> [--slug <s>]` copies a qualifying kit into `.aimi/sources/<slug>-<hash8>/` and prints `{dir, htmlFiles, markdownFiles, otherFiles, reused}` with every path relative to the AIMI root. `kind` is `folder` or `zip`; member paths are relative to the kit after a single top-level folder is flattened; `qualifies` is true only when at least one `.html` member exists and `refused` is empty. The directory is `<slug>-<hash8>`: the slug comes from `--slug` or the kit's basename through `slug.py`'s `slugify`, and hash8 is the first 8 hex digits of a SHA-256 over the sorted member names and bytes, so re-importing identical content prints the existing dir with `reused: true` and writes nothing, and different content gets a different dir. The original kit is never modified.

Both verbs validate every member before anything is written. **Member refusals** (`import` exits 1 naming each member and reason on stderr, `inspect` lists them in `refused`): an absolute name or a `..` segment, a symlink (zip external attributes or an on-disk link), a member under `.git/` or `.claude/`, and a file named `CLAUDE.md`, `AGENTS.md` or `settings.json` (case-insensitive). `__MACOSX/` members and `.DS_Store` files are skipped, neither copied nor counted. **Archive-level refusals** exit 1 with a reason on stderr and nothing on stdout or disk, from both verbs: a path that is neither a directory nor a `.zip`, a corrupt zip (bad central directory or CRC), an encrypted member, a non-ASCII member name without the UTF-8 flag, more entries than `MAX_ENTRIES` (2000), more uncompressed bytes than `MAX_TOTAL_BYTES` (64 MiB, counted from bytes actually read), a member that is not a regular file, and two members flattening to one name. The path argument is confined by `validate_path_in_project` before `python3` starts. The copy is built in a `mkdtemp` directory under `.aimi/sources/` and renamed into place. Both verbs need `python3` (`prototype_kit.py`, run with `-I`) and refuse without it, so a missing interpreter never reads as "not a kit". `inspect-prototype-kit` is in `hooks/auto-approve-cli.sh` Pattern 2; `import-prototype-kit` is not and prompts. Tests: `scripts/tests/test_prototype_kit.py`.

### `index-prototype-anchors` and the kind-tagged anchors of `extract-prototype-sections`

A prototype with no `data-view` section cannot be sliced by view name, so `aimi-cli.sh index-prototype-anchors <file>` lists what it can be sliced by: one `<kind>:<name>` line per anchor, in document order, every line one `extract-prototype-sections --anchors` accepts verbatim. The kinds are `view` (a `<section data-view>`), `id` (an `id` on `section`, `main`, `article` or `div`), `tab` (a `role=tabpanel`, named by the text of the element its `aria-labelledby` names, else of the `role=tab` element whose `aria-controls` names it, else its `aria-label`) and `heading` (`h1` to `h3`, whitespace collapsed). A repeated `kind:name` is listed once; an `id` container that encloses every other anchor of the file (an `#app` wrapper) is left out, and a container with nothing else to enclose stays; a name holding `$`, a backtick, a double quote or a backslash is left out with a `Warning: anchor skipped (unsafe character)` line on stderr, since the extract verbs reject those characters. A file with no anchor prints nothing at exit 0. The path is confined like the two extract verbs (`resolve_path` plus `validate_path_in_project` before `python3` starts, and the verb is in `_PATH_ARG_POSITIONAL_VERBS`), the verb needs `python3` and refuses without it.

`extract-prototype-sections` accepts the same lines. `id:` and `tab:` print the element from its opening tag through its matching closing tag, to end of file when it is never closed; `heading:` prints from the heading's opening tag up to the next `h1`-`h6` of the same or a higher level, or end of file, looking at start tags only so unbalanced markup does not change the answer. Every slice is cut from the raw text by the parser's own offsets and never re-serialised, so it is the bytes on disk (CRLF and non-ASCII text included), and nothing is added between two slices. A bare anchor and a `view:` anchor keep the awk data-view slicing byte for byte and still run without `python3`; any other kind refuses at exit 1 through `check_python3` when it is missing. The metacharacter rejection applies to the whole anchor, so after the kind prefix too, and an unmatched anchor of any kind keeps the `no section matched anchor` warning at exit 0. The HTML rules are all in `scripts/prototype_anchors.py` (`html.parser`, two passes so a panel can be named by a tab that follows it), run with `-I`, one crossing per kind-tagged anchor so request order is kept. Tests: `scripts/tests/test_prototype_anchors.py`.

### `detect-design-bundle --feature-stdin`

A stray or placeholder bundle left in the tree carries the same README marker as the real one, so a scan used to elect it or tie and refuse. `--feature-stdin` reads the feature description from stdin (never an argument) and hands it, with the scan-tier candidates as argv, to `scripts/bundle_relevance.py`, which keeps a candidate only when its directory name or the first H1 of its `project/BusinessSpec.md` shares at least one token with the description. Tokens are `ascii_fold`ed runs of `[a-z0-9]` of at least 3 characters minus English and Portuguese stop-words and a short list of generic app words, and the description is capped at 2000 characters before folding. Zero relevant bundles prints `null`, one prints that bundle, and two or more refuse with exit 3 listing only the relevant ones; the discarded paths go to stderr and into a `filtered[]` array on the JSON object outputs. A description with no token left (empty, whitespace, only stop-words) turns the filter off and adds no `filtered` key. The phase tier, `--bundle` and `--all` are never filtered, and without the flag every output is unchanged. It requires `python3` and refuses with exit 1 without it. Tests: `scripts/tests/test_bundle_relevance.py` and the `--feature-stdin` cases in part 3 of `test-aimi-cli.sh`.
